Refactoring Technique

Improving Architecture

Improving Architecture focuses on high-level refactoring that reorganizes systemic boundaries, separates concerns across architectural layers, and establishes clear communication patterns between subsystems. While class-level refactorings clean up individual components, architectural refactoring ensures the overall system remains scalable, maintainable, and adaptable to changing business needs.

As systems mature, features are often patched across boundary lines, creating monolithic coupling, tangled dependencies, and blurred layer responsibilities. Re-architecting incrementally enables teams to transition from rigid, tightly coupled systems toward modular architectures (such as Clean Architecture, CQRS, or Domain-Driven Design) without disrupting operational stability.

Key Takeaways

  • Establishes strict boundaries between Presentation, Domain, Infrastructure, and Data Access layers.
  • Protects core business logic from UI frameworks, database drivers, and external API changes.
  • Facilitates high-level system testability through contract-driven integration and boundary mocking.
  • Enables team independence by allowing distinct modules to be developed, deployed, or scaled separately.

When & How to Apply

Apply this technique when UI components execute database queries directly, domain logic relies on third-party SDKs, or data persistence models leak into API view representations:

  • Separate Domain from Infrastructure: Move core business rules and entities into an independent domain layer free of framework-specific dependencies.
  • Apply Command-Query Responsibility Segregation (CQRS): Separate read-heavy queries from state-mutating commands to optimize performance and security boundaries.
  • Introduce Repository & Unit of Work Patterns: Abstract data access routines behind clean collection-oriented interfaces.
  • Use Event-Driven Integration: Replace direct cross-module method invocations with domain events to decouple secondary side effects.

Example / Usage

// BEFORE: Monolithic API Controller mixing HTTP handling, database queries, business rules, and emailing
public class OrderController
{
    public void PlaceOrder(int customerId, List<int> productIds)
    {
        using var db = new SqlConnection("Server=myServerAddress;Database=myDataBase;");
        db.Open();

        // Database logic directly inside presentation/controller layer
        var user = db.QuerySingle("SELECT * FROM Users WHERE Id = " + customerId);
        decimal total = 0;
        foreach (var id in productIds)
        {
            var price = db.QuerySingle<decimal>("SELECT Price FROM Products WHERE Id = " + id);
            total += price;
        }

        // Direct persistence write
        db.Execute($"INSERT INTO Orders (UserId, Total) VALUES ({customerId}, {total})");

        // Infrastructure call coupled inside HTTP endpoint
        var smtp = new SmtpClient("smtp.mailserver.com");
        smtp.SendMail(user.Email, "Order Confirmed", $"Total charged: {total:C}");
    }
}

// AFTER (C#): Multi-layered architecture enforcing clean boundaries via Mediating Commands & Interfaces
public record PlaceOrderCommand(int CustomerId, List<int> ProductIds) : IRequest<bool>;

// Application Layer: Coordinates workflow without raw SQL or SMTP framework details
public class PlaceOrderCommandHandler
{
    private readonly ICustomerRepository _customerRepository;
    private readonly IOrderRepository _orderRepository;
    private readonly INotificationService _notificationService;

    public PlaceOrderCommandHandler(
        ICustomerRepository customerRepository,
        IOrderRepository orderRepository,
        INotificationService notificationService)
    {
        _customerRepository = customerRepository;
        _orderRepository = orderRepository;
        _notificationService = notificationService;
    }

    public async Task<bool> Handle(PlaceOrderCommand command)
    {
        var customer = await _customerRepository.GetByIdAsync(command.CustomerId);
        var order = Order.Create(customer, command.ProductIds); // Rich Domain Model encapsulates logic

        await _orderRepository.SaveAsync(order);
        await _notificationService.SendOrderConfirmationAsync(customer.Email, order.Total);

        return true;
    }
}

// Presentation Layer: Lightweight delegate passing input to the architectural boundary
public class OrderControllerRefactored
{
    private readonly IMediator _mediator;

    public OrderControllerRefactored(IMediator mediator) => _mediator = mediator;

    public async Task<IActionResult> PlaceOrder([FromBody] PlaceOrderCommand command)
    {
        var result = await _mediator.Send(command);
        return result ? Ok() : BadRequest();
    }
}
