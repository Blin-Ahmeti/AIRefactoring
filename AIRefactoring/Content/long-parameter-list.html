Code Smell

Long Parameter List

A Long Parameter List occurs when a method or constructor accepts too many parameters—typically more than three or four. Long parameter lists make code hard to read, difficult to call correctly, and prone to subtle bugs caused by passing arguments in the wrong order (especially when multiple parameters share the same data type).

This smell often develops when procedural code is adapted for object-oriented systems, or when developers continuously pass flags and configuration details down through multiple layers of method calls instead of passing objects that already encapsulate those values.

Key Takeaways

  • Decreases readability and developer productivity by requiring constant checking of parameter order and types.
  • High vulnerability to silent bugs when adjacent parameters share types (e.g., multiple consecutive string or bool values).
  • Creates rigid coupling between callers and callees whenever method signatures change.
  • Often signals that the method is taking on too many responsibilities or missing a cohesive domain abstraction.

When & How to Refactor

Refactor long parameter lists whenever calling a method feels clumsy or requires constantly inspecting its signature:

  • Introduce Parameter Object: Group related parameters into a single class or struct (e.g., combining startDate and endDate into a DateRange object).
  • Preserve Whole Object: Instead of extracting multiple values from an object and passing them individually, pass the original object itself.
  • Replace Parameter with Method Call: If a parameter value can be retrieved by invoking another method on an existing object, remove the parameter and call that method internally.

Example / Usage

// BEFORE: A method taking a long list of individual user creation parameters
public class UserService
{
    public void RegisterUser(
        string firstName, 
        string lastName, 
        string email, 
        string street, 
        string city, 
        string zipCode, 
        string country, 
        bool sendWelcomeEmail)
    {
        // Registration and address processing logic...
        Console.WriteLine($"Registering {firstName} {lastName} living in {city}, {country}.");
    }
}

// AFTER (C#): Refactored using Parameter Objects (Address & Registration Request DTOs)
public record Address(string Street, string City, string ZipCode, string Country);

public class UserRegistrationRequest
{
    public string FirstName { get; set; } = string.Empty;
    public string LastName { get; set; } = string.Empty;
    public string Email { get; set; } = string.Empty;
    public Address Address { get; set; } = null!;
    public bool SendWelcomeEmail { get; set; } = true;
}

public class UserServiceRefactored
{
    public void RegisterUser(UserRegistrationRequest request)
    {
        // Clean, readable method signature and parameter access
        Console.WriteLine($"Registering {request.FirstName} {request.LastName} living in {request.Address.City}, {request.Address.Country}.");
    }
}
