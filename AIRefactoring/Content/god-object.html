Code Smell

God Object

A God Object (also known as a God Class or Omniscient Class) is an anti-pattern and extreme form of the Large Class code smell. It refers to an object that knows too much or does too much, centralization of an application's overall processing, state, and business rules into a single monolithic entity.

God Objects turn object-oriented software into procedural code. Surrounding classes are reduced to passive data holders (Anemic Domain Models) with simple getters and setters, while the God Object orchestrates every operation. This creates a fragile, highly coupled architecture where even minor changes carry severe regression risks across the system.

Key Takeaways

  • Completely destroys modularity and encapsulation by hoarding data and control flow.
  • Leads to massive file sizes (thousands of lines of code) that hinder developer comprehension and team collaboration.
  • Triggers constant merge conflicts and compile-time bottlenecks in multi-developer environments.
  • Makes unit testing nearly impossible due to deeply entangled global state and unmockable dependencies.

When & How to Refactor

Refactoring a God Object requires decomposing it into smaller, cohesive domain components:

  • Extract Class: Break off logical sub-domains (e.g., authentication, billing, notifications) into independent classes.
  • Move Method & Move Field: Relocate methods and fields back into the passive data classes they operate on, restoring true Object-Oriented behavior.
  • Facade / Mediator Pattern: Replace the monolithic manager with lightweight facade or mediator services that coordinate specialized components.

Example / Usage

// BEFORE: A God Object holding all state and executing all operations across sub-domains
public class SystemManager
{
    // Customer state & actions
    public string CustomerName { get; set; } = string.Empty;
    public string CustomerEmail { get; set; } = string.Empty;

    // Inventory state & actions
    public Dictionary<string, int> Inventory { get; set; } = new();

    // Order state & actions
    public List<string> OrderHistory { get; set; } = new();

    public void ExecuteFullSystemCycle(string item, int qty)
    {
        // 1. Inventory check
        if (Inventory.ContainsKey(item) && Inventory[item] >= qty)
        {
            Inventory[item] -= qty;

            // 2. Order creation
            OrderHistory.Add($"Ordered {qty}x {item}");

            // 3. Email notification
            Console.WriteLine($"Sending confirmation email to {CustomerEmail}...");
        }
    }
}

// AFTER (C#): Decoupled into specialized domain objects co-locating data and behavior
public class Customer
{
    public string Name { get; set; } = string.Empty;
    public string Email { get; set; } = string.Empty;
}

public class InventoryService
{
    private readonly Dictionary<string, int> _stock = new();

    public bool TryDeductStock(string item, int quantity)
    {
        if (_stock.TryGetValue(item, out int count) && count >= quantity)
        {
            _stock[item] -= quantity;
            return true;
        }
        return false;
    }
}

public class OrderProcessor
{
    private readonly InventoryService _inventory;
    private readonly INotificationService _notifier;

    public OrderProcessor(InventoryService inventory, INotificationService notifier)
    {
        _inventory = inventory;
        _notifier = notifier;
    }

    public bool PlaceOrder(Customer customer, string item, int quantity)
    {
        if (!_inventory.TryDeductStock(item, quantity)) return false;

        _notifier.SendEmail(customer.Email, $"Order placed for {quantity}x {item}");
        return true;
    }
}
