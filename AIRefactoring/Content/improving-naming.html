Refactoring Technique

Improving Naming

Improving Naming is the refactoring practice of replacing vague, misleading, or overly abbreviated names with clear, self-explanatory identifiers for variables, methods, parameters, and classes. Code is read far more often than it is written, making expressive naming one of the most effective ways to lower cognitive load and convey developer intent.

Cryptic identifiers like single-letter variables, magic constants, or generic function names force developers to read through entire method implementations just to deduce what a value represents. By adopting intent-revealing names, the code becomes self-documenting, reducing the reliance on easily outdated comments.

Key Takeaways

  • Makes code self-documenting, significantly reducing the need for line-level comments.
  • Decreases developer onboarding time and accelerates daily code reviews.
  • Eliminates ambiguity around units of measurement, domain contexts, and boolean states.
  • Prevents accidental bugs caused by misinterpreting what a method or variable actually does.

When & How to Apply

Apply this technique whenever a name requires mental translation or fails to explicitly describe its purpose:

  • Rename Method / Variable: Use modern IDE automated refactoring tools to rename cryptic variables or functions across the entire solution safely.
  • Express Intent Over Implementation: Name methods after what they achieve rather than how they perform it internally.
  • Use Pronounceable & Searchable Names: Avoid obscure abbreviations or single-letter names (except for standard short loop counters like i).
  • Incorporate Units or Context: Append explicit terms when working with quantities or durations (e.g., timeoutInMilliseconds or priceInUsd).

Example / Usage

// BEFORE: Cryptic variable names, magic numbers, and unclear method intent
public class Processor
{
    // What do these numbers or variables mean without reading the code?
    public decimal Calc(decimal p, int t)
    {
        decimal d = 0;
        if (t == 1)
        {
            d = p * 0.10m;
        }
        else if (t == 2)
        {
            d = p * 0.20m;
        }
        return p - d;
    }
}

// AFTER (C#): Self-documenting code using expressive names and clear domain enums
public enum CustomerTier
{
    Standard = 1,
    Premium = 2
}

public class DiscountCalculator
{
    private const decimal StandardDiscountRate = 0.10m;
    private const decimal PremiumDiscountRate = 0.20m;

    public decimal CalculateFinalPrice(decimal originalPrice, CustomerTier tier)
    {
        decimal discountAmount = tier switch
        {
            CustomerTier.Standard => originalPrice * StandardDiscountRate,
            CustomerTier.Premium  => originalPrice * PremiumDiscountRate,
            _                     => 0m
        };

        return originalPrice - discountAmount;
    }
}
