Refactoring Technique

Improving Conditionals and Control Flow

Improving Conditionals and Control Flow is a targeted refactoring technique focused on simplifying branching logic, untangling nested conditional trees, and eliminating state-tracking control flags. Control flow structures often become overly complex as new business rules and edge cases are added over time.

Complex conditional logic forces developers to keep multiple mental states in mind while reading code. By consolidating duplicate branches, decomposing boolean expressions, replacing switch statements with pattern matching, or replacing complex evaluation trees with lookup tables, control flow becomes linear and predictable.

Key Takeaways

  • Flattens complex control trees into clear, linear execution flows.
  • Consolidates identical outcome branches to reduce boilerplate and duplication.
  • Replaces imperative state-tracking flags with explicit break, continue, or early return statements.
  • Leverages modern C# pattern matching and switch expressions to make branching logic concise and self-documenting.

When & How to Apply

Apply this technique whenever conditional branching spans multiple nesting levels or when branch conditions are difficult to decipher:

  • Consolidate Conditional Expression: If a sequence of conditional checks leads to the same outcome, combine them into a single compound expression using logical operators.
  • Decompose Conditional: Extract complex boolean evaluations into private, well-named predicate helper methods.
  • Replace Control Flag with Break/Return: Remove temporary boolean flags (e.g., bool isDone = false;) used solely to exit loops or control branching.
  • Replace Switch/If with Pattern Matching or Dictionary Lookup: Simplify complex type or value checking by utilizing C# switch expressions or key-based action lookups.

Example / Usage

// BEFORE: Deeply nested conditional branching, magic numbers, and control flags
public class ShippingRateCalculator
{
    public decimal GetRate(string destination, double weight, bool isExpress)
    {
        decimal rate = 0;
        bool isHandled = false;

        if (destination == "US" || destination == "CA")
        {
            if (weight < 5.0)
            {
                if (isExpress)
                {
                    rate = 15.00m;
                    isHandled = true;
                }
                else
                {
                    rate = 8.00m;
                    isHandled = true;
                }
            }
            else
            {
                rate = isExpress ? 25.00m : 14.00m;
                isHandled = true;
            }
        }

        if (!isHandled)
        {
            rate = isExpress ? 50.00m : 30.00m;
        }

        return rate;
    }
}

// AFTER (C#): Clean control flow using Guard Clauses, C# Pattern Matching, and Switch Expressions
public class ShippingRateCalculatorRefactored
{
    public decimal GetRate(string destination, double weight, bool isExpress)
    {
        bool isNorthAmerica = destination is "US" or "CA";

        return (isNorthAmerica, weight, isExpress) switch
        {
            (true, < 5.0, true)   => 15.00m,
            (true, < 5.0, false)  => 8.00m,
            (true, _, true)       => 25.00m,
            (true, _, false)      => 14.00m,
            (false, _, true)      => 50.00m,
            (false, _, false)     => 30.00m
        };
    }
}
