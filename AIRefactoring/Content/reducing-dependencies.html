Refactoring Technique

Reducing Dependencies

Reducing Dependencies is a set of refactoring techniques targeted at minimizing tight coupling between modules, classes, and external libraries. When components are deeply interconnected, a change in one class often triggers a cascade of unexpected breakages throughout the system.

By breaking direct concrete dependencies and introducing abstractions, dependency injection, and event-driven patterns, software becomes modular. Reducing dependencies ensures that components can be developed, tested, updated, or swapped independently without impacting the rest of the application.

Key Takeaways

  • Prevents cascading failures across unrelated modules when business requirements change.
  • Enables isolated unit testing by replacing concrete infrastructure calls with test doubles (mocks/stubs).
  • Adheres to the Dependency Inversion Principle (DIP) and Law of Demeter.
  • Reduces compilation times and simplifies package management by lowering inter-module reliance.

When & How to Apply

Apply this technique when classes directly instantiate high-level services, navigate long object chains (e.g., a.GetB().GetC().DoSomething()), or directly depend on volatile third-party frameworks:

  • Dependency Injection (DI): Invert control by injecting dependencies via interfaces in class constructors instead of using new internally.
  • Hide Delegate / Demeter Fix: Encapsulate nested delegation so callers do not need knowledge of hidden intermediate objects.
  • Introduce Adapter / Facade: Wrap third-party libraries behind internal domain interfaces to isolate vendor changes.
  • Replace Hardcoded References with Events/Observers: Decouple producers from consumers using events or mediator patterns.

Example / Usage

// BEFORE: Tightly coupled to concrete SQL database connection and SMTP client inside the business logic
public class OrderService
{
    public void FinalizeOrder(int orderId, string customerEmail)
    {
        // Direct instantiation of concrete infrastructure components
        var db = new SqlDatabaseConnection("Server=myServerAddress;Database=myDataBase;");
        db.ExecuteQuery($"UPDATE Orders SET Status = 'Completed' WHERE Id = {orderId}");

        var smtp = new DirectSmtpClient("smtp.mailserver.com");
        smtp.SendMail(customerEmail, "Order Completed", "Your order has been processed.");
    }
}

// AFTER (C#): Decoupled dependencies using interfaces and Constructor Injection
public interface IOrderRepository
{
    void CompleteOrder(int orderId);
}

public interface INotificationService
{
    void SendNotification(string recipient, string subject, string body);
}

public class OrderServiceRefactored
{
    private readonly IOrderRepository _repository;
    private readonly INotificationService _notifier;

    // Dependencies are injected via interfaces, making the class easy to test and extend
    public OrderServiceRefactored(IOrderRepository repository, INotificationService notifier)
    {
        _repository = repository ?? throw new ArgumentNullException(nameof(repository));
        _notifier = notifier ?? throw new ArgumentNullException(nameof(notifier));
    }

    public void FinalizeOrder(int orderId, string customerEmail)
    {
        _repository.CompleteOrder(orderId);
        _notifier.SendNotification(customerEmail, "Order Completed", "Your order has been processed.");
    }
}
