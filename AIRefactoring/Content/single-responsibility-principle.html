Refactoring Principle

Single Responsibility Principle (SRP)

The Single Responsibility Principle (SRP) is the first principle of SOLID, formulated by Robert C. Martin. It states that "A class should have one, and only one, reason to change." In other words, a single module, class, or function should be responsible for only one specific actor, role, or domain concern within the software.

When a class attempts to handle multiple distinct responsibilities—such as mixing database persistence, business rules, and presentation formatting—it becomes fragile. Changes requested by one stakeholder (e.g., changing the invoice PDF layout) risk breaking functionality relied on by another (e.g., tax computation logic).

Key Takeaways

  • High cohesion and low coupling across classes and modules.
  • Easier maintenance: changes to one domain area do not ripple into unrelated functionality.
  • Significantly improved unit testing, as dependencies can be easily mocked or tested in isolation.
  • Prevents "God Objects" that swell to thousands of lines and become unmaintainable over time.

When & How to Apply

Apply SRP when you notice a class handling multiple distinct tasks or serving different actors. Common refactoring techniques to enforce SRP include Extract Class and Extract Method. If describing what a class does requires using the word "and" repeatedly, it is a strong signal that SRP is being violated.

Example / Usage

// BEFORE SRP VIOLATION: One class handles business calculations, formatting, AND persistence
public class Invoice {
  private double amount;

  public Invoice(double amount) {
    this.amount = amount;
  }

  public double calculateTotal() {
    return this.amount * 1.20; // Includes tax
  }

  public void saveToDatabase() {
    System.out.println("Saving invoice to database...");
  }

  public String generateHtmlReport() {
    return "<div>Invoice Total: " + calculateTotal() + "</div>";
  }
}

// AFTER SRP: Separated into dedicated classes with single, well-defined roles
public class Invoice {
  private double amount;

  public Invoice(double amount) {
    this.amount = amount;
  }

  public double calculateTotal() {
    return this.amount * 1.20;
  }
}

public class InvoiceRepository {
  public void save(Invoice invoice) {
    System.out.println("Saving invoice to database...");
  }
}

public class InvoiceFormatter {
  public String toHtml(Invoice invoice) {
    return "<div>Invoice Total: " + invoice.calculateTotal() + "</div>";
  }
}
